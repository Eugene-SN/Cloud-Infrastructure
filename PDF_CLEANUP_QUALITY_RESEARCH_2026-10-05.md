# Расширенное исследование качества PDF cleanup — 2026-10-05

**Статус: RESEARCH / NOT DEPLOYED.** Исследование выявило риски потери
полезного текста, которые важнее исходных пяти отказов. Исправлять следует
автономный CLI; дополнительные проверки и узлы в n8n для этого не нужны.
Экспериментальный патч не является готовым production обновлением.

## Объём и условия

Подтверждено: в originals 95 PDF по 14 моделям, из них 49 уникальных по SHA256,
6398 страниц. Одинаковые файлы исследованы один раз с сохранением всех путей.
Проверены текущие документы Lenovo ASP и Lenovo Press из существующего каталога;
это не доказательство поддержки любых будущих PDF.

База — установленный импорт Eugene-SN/documentation-ai,
`46f179e9e5c83ff2c12b7ba084efef124afaf338`; package 0.1.3.
Фактический runtime: Python 3.14.8, PyMuPDF/MuPDF 1.28.2, pypdf 6.19.0,
cryptography 50.0.2. Исследования выполнялись в существующем Docker image по
неизменяемому ID, на read-only снимках в `/tmp`, без сетевого доступа контейнера.
PDFium и FontTools устанавливались только во временные исследовательские каталоги.

Серия была итеративной: V1 создал 46 проверенных штатным механизмом результатов;
V4 повторно проверил их усиленным validator и сравнил планы удаления;
V6 исправил три оставшихся отказа. Это **не** полный регрессионный прогон
одного окончательного варианта V6. Независимая проверка охватила результаты
всех 49 уникальных документов, все 6398 страниц.

## Что выявлено

### 1. Возможна ошибочная классификация полезного текста

Подтверждено на синтетическом PDF: строки `Required setting 1` и
`Required setting 2` на высоте 200 pt принимаются за колонтитулы. И установленный
алгоритм, и прототип удаляют их с результатом `validation=passed`.

Подтверждено при **повторном анализе уже очищенного** WR5220 G5 User Guide v7:
предлагается удалить подписи USB/OCP на физических страницах 35–36:
`7 USB 3.0 接口（2）`, `8 OCP 模块上的以太网接口`,
`9 OCP 模块上的以太网接口`. Их baseline около 658 pt на странице высотой 792 pt;
исходные настоящие колонтитулы расположены около 756 pt.
Это анализ плана, не публикация повторно повреждённого документа.

Из 46 результатов при повторном анализе 43 не имеют целей удаления,
один выбирает эти полезные строки, два отказывают из-за неоднозначной нумерации
(OneCLI cPlus и WR5220 G3 User Guide). Идемпотентность не подтверждена.
Текущая автоматизация обрабатывает originals, поэтому этот эксперимент
не доказывает удаление USB/OCP в действующем первом запуске.

Причина: последовательные числа и положение последней строки недостаточны,
чтобы отличить колонтитул от основного текста. Validator проверяет сохранность
относительно плана удаления, но не семантическую правильность самого плана.
[Документация pypdf](https://pypdf.readthedocs.io/en/6.19.0/user/extract-text.html)
также описывает неоднозначность структуры PDF и координат сложных объектов.

**Приоритет:** отдельно проверять распознавание области колонтитула — по
положению относительно видимой страницы, устойчивому расположению в документе
и native Pagination tags, когда они есть. Затем удалять только точные фрагменты,
без широких полос. Конкретные пороги ещё не выбраны и не приняты оператором.
Эксперимент с обязательным большим пробелом между номером и подписью отклонён:
он пропускал настоящие колонтитулы Lenovo Press lp2469.

### 2. Региональная redaction может изменить полезный текст

На WR6220 G5 User Guide, физическая страница 349, независимый PDFium выявил
изменение `Energy Perf BIAS` → `EnergyPerf BIAS` и смещение восьми символов
примерно на 4.4 pt. Просмотр исходного и выходного растра подтвердил изменение
в таблице основного текста. Проверки MuPDF, включая усиленную, его пропустили.

По всем 49 результатам независимая проверка дала **42 без расхождений и 7
с расхождениями вне точных масок удаления**:

| Документ | Страницы с расхождениями | Пиксели вне масок, 144 dpi |
| --- | ---: | ---: |
| WA5680 G3 User Guide | 1 | 166 |
| BMC Event Reference G5 v4 | 1 | 10 |
| OS Installation Guide | 37 | 547 |
| WA7785a G3 BIOS User Guide | 1 | 129 |
| WR6220 G5 User Guide | 2 | 1022 |
| WA7880a G3 User Guide | 1 | 212 |
| Lenovo Press lp1728 | 2 | 145 |

У шести документов извлечённые непробельные символы и их позиции сохранились;
причины небольших изменений изображения ещё не установлены. Проверка с
отключением отображения annotations не объяснила изменения исследованных
страниц. Эти различия **не объявлены безвредными**.

**Рекомендация:** исследовать удаление точных текстовых операторов и выбор
метода на уровне страницы. Простая замена redaction на операторный метод для
всего WR6220 не прошла усиленную проверку — отказ на странице 14, выходной файл
не опубликован. Универсальная замена метода пока не обоснована.

### 3. Устранены конкретные причины отказов трёх руководств

В изолированном прототипе:

- Для иллюстраций учитываются реальная clipping область и структура drawing
  groups. Геометрический bbox скрытой части рисунка больше не считается таблицей.
- Одиночная Roman `i` подтверждается следующей согласованной decimal последовательностью;
  произвольный одиночный номер по-прежнему не принимается.
- Наличие вложенных body Forms не мешает сопоставлять верхнеуровневые текстовые
  операторы страницы. При записи создаётся частный `/Contents`, без изменения
  общих исходных streams.
- Для отдельного текстового Footer Form удаляется конкретный вызов `Do`, только
  если все его текстовые позиции соответствуют выбранным строкам и нет рисования,
  изображений или вложенных Forms. Содержимое Form не меняется; его использование
  в основном тексте сохраняется.
- Пересечение bbox основного текста и footer не означает реального пересечения
  нарисованных букв. На WR5225 G3, странице 296, пересечение около 0.9 pt
  устраняется удалением точных операторов вместо региональной redaction.

Результаты последней отдельной серии:

| Документ | Страниц | CLI, секунд | Независимый PDFium |
| --- | ---: | ---: | --- |
| WA7780 G3 User Guide | 100 | 321.039 | без расхождений |
| WA7785a G3 User Guide | 98 | 262.776 | без расхождений |
| WR5225 G3 User Guide v6 | 375 | 125.372 | без расхождений |

Сохранность изображений, векторов, основного текста и свойств документа проверена.
Это подтверждает эти случаи, а не универсальную пригодность всего прототипа.
Механизмы проверены по
[PyMuPDF drawing API](https://pymupdf.readthedocs.io/en/latest/page.html#Page.get_drawings),
[Contents API](https://pymupdf.readthedocs.io/en/latest/functions.html#Page.set_contents)
и [точному исходному коду pypdf 6.19.0](https://raw.githubusercontent.com/py-pdf/pypdf/6.19.0/pypdf/_page.py).

### 4. `garbage=2` оправдан качеством результата, а не только скоростью

Для BMC G3 Redfish Guide v11: 423 страницы, 113763 xref, нет footer/widgets,
но есть 133 удаляемые ссылки. Копирование без очистки здесь было бы неверным.

Изменение только save options установленного CLI на
`garbage=2, deflate=True, use_objstms=1` дало:

- сохранение 0.658 s; весь cleanup 88.997 s;
- размер 5894615 bytes против исходных 8326662 bytes;
- удалены 107 `/Dest` и 26 `/URI`;
- штатная проверка сохранности пройдена.

В отдельной корпусной генерации Redfish с теми же save options независимая
проверка всех 423 страниц не нашла изменений вне масок; основной текст и свойства
документа сохранились. SHA256 этого результата отличается от benchmark output;
независимая проверка относится к корпусному результату, а не к байтам benchmark.

Контрольный `garbage=3` остановлен после 1843.457 s, пока оставался в save.
Это незавершённый эксперимент: размера и verdict его выходного PDF нет.
Предыдущий эксперимент с `garbage=2` без object streams давал 17340426 bytes.

`garbage=3` добавляет объединение дублирующихся объектов, а object streams
уплотняют хранение без потерь. Эти настройки не уменьшают разрешение изображений
и не растеризуют текст. Это подтверждается
[официальным контрактом save](https://pymupdf.readthedocs.io/en/latest/document.html#Document.save)
и [исходниками MuPDF 1.28.2](https://raw.githubusercontent.com/ArtifexSoftware/mupdf/1.28.2/source/pdf/pdf-write.c).
Приведённый эксперимент подтверждает сохранность именно проверенного файла.

### 5. Validator следует усилить внутри CLI

Отрицательные синтетические тесты подтвердили пробелы установленной проверки:
изменение размера/шрифта, цвета, прозрачности и порядка чтения может остаться
незамеченным при сохранённых координатах символов. Прототип проверяет эти свойства.
Это недостатки проверки, не свидетельство таких изменений в production файлах.
[TextPage API](https://pymupdf.readthedocs.io/en/latest/textpage.html)
предоставляет соответствующие свойства spans.

Независимый PDFium контролирует все страницы в 144 dpi, текст и координаты,
bookmarks, page labels, metadata и XML metadata. Маски — только bbox конкретных
удаляемых фрагментов/widgets, с запасом два raster pixels для anti-aliasing.
Нельзя маскировать всю нижнюю полосу: это скрыло бы повреждения.
[PDFium API](https://pypdfium2.readthedocs.io/en/stable/python_api.html).

Первоначальный verifier ошибочно считал лишними **сохранённые** буквы внутри масок.
Контроль на идентичном PDF подтвердил дефект нашего verifier. Исправлен только
этот текстовый контроль, повторно проверены все 46 результатов с подтверждением
хешей; уже полученные raster/property результаты сохранены. Три ложных сигнала
lp1705/lp2356/lp2014 исчезли. Отдельный runner также исправлен после отсутствующего
`widget_masks` в записи WR5225: подтверждён ноль удалённых widgets, продолжена
только незавершённая проверка. Это дефекты исследовательской обвязки, не production.

### 6. Отсутствие целей очистки — успешная точная копия

Если анализ не находит **ни колонтитулов, ни ссылок, ни target widgets**, прототип
копирует PDF без пересохранения с равенством SHA256. При наличии других целей
очистка выполняется полностью. Отказ проверки не превращается в успешную копию.

FontTools 4.66.1 проверен на 12 Lenovo Press PDF: результаты извлечения текста
и native evidence идентичны с библиотекой и без неё; CFF dependency warnings
исчезают у трёх документов. Это возможное дополнение поддержки шрифтов,
не исправление наблюдаемых отказов и не обязательный production компонент.
[pypdf CFF implementation](https://raw.githubusercontent.com/py-pdf/pypdf/6.19.0/pypdf/_cmap.py).

   кейсы из настоящего WR5220 G5; проверить первое и повторное применение.
2. Разобрать различия на WR6220 и остальных шести документах; выбрать метод
   удаления для конкретной страницы по проверяемому результату, без filename profiles.
3. Объединить подтверждённые исправления в один CLI candidate. Провести единый
   полный прогон всех 49 уникальных PDF с независимым renderer, включая пробелы
   и свойства документа. Только после этого обсуждать production обновление.

Сам контракт остаётся простым: `pdf-cleanup INPUT.pdf OUTPUT.pdf`, JSON результат,
без новых daemon/API/queue. n8n передаёт файлы и публикует прошедший проверку output.
Защита originals и структура `originals/<model>/`, `cleaned/<model>/`,
`translated/<language>/<model>/` сохраняются.

## Evidence и неизменность production

Артефакты: [каталог исследования](deployments/edge/pdf-cleanup/quality-research-2026-10-05/README.md),
[evidence](deployments/edge/pdf-cleanup/quality-research-2026-10-05/evidence.json),
экспериментальный патч, воспроизводящие scripts и контрольные логи.

Финальные контроли прототипа: 23 теста, из них 22 успешных и один явный
expected failure для известной ошибки классификации. Неизменённый upstream/edge
suite: 13 из 14 успешны, включая все три originals guard теста. Один прежний
тест ожидает отказ при пересечении bbox; V6 вместо отказа сохраняет основной
текст операторным методом. Отдельный положительный контроль подтвердил сохранение
`OVERLAPPING BODY`. Прежнее ожидание теста не скрыто и не переписано.

Контроль SHA256 111 существующих файлов — 95 originals PDF, 14 cleaned PDF,
INDEX.html и INDEX.md — не выявил изменений. Установленные core/native, launcher,
adapter и Docker image ID сохранены. Workflow не редактировались и не запускались
этим исследованием. Временные исследовательские контейнеры и данные удалены;
PDF, raster previews и сторонние библиотеки в Git не сохранены.
