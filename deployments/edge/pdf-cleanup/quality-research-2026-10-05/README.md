# Изолированное исследование качества PDF cleanup

Статус: **RESEARCH / NOT DEPLOYED**. Это материалы исследования, а не
готовое обновление production. Патч содержит экспериментальные изменения;
универсальная точность распознавания колонтитулов ещё не доказана.

Полный отчёт: `PDF_CLEANUP_QUALITY_RESEARCH_2026-10-05.md` в корне репозитория.
`evidence.json` содержит версии, хеши, результаты каждого уникального документа,
проверки неизменности исходных данных и ограничения экспериментов.

## Воспроизведение

База патча — фактически установленное содержимое `/opt/pdf-cleanup/source`,
импортированное из Eugene-SN/documentation-ai, commit
`46f179e9e5c83ff2c12b7ba084efef124afaf338`, с существующим edge guard.
Базовые и конечные SHA256 записаны в evidence. `candidate-v6.patch` меняет только
`src/pdf_cleanup/core.py` и `src/pdf_cleanup/native.py`. Guard не ослаблен.
Патч применять к отдельной копии исходников, а не к `/opt/pdf-cleanup/source`.

Проверенный runtime: существующий image ID из evidence, Python 3.14.8,
PyMuPDF/MuPDF 1.28.2, pypdf 6.19.0. Для независимой проверки использованы
pypdfium2 5.14.0 / PDFium 156.0.8076.0, NumPy 2.5.3 и Pillow 12.3.0
в отдельном временном каталоге. FontTools 4.66.1 исследован отдельно.
В production зависимости не устанавливались.

Research scripts ожидают контейнерные пути:

- `/audit`: read-only каталог исследования с `manifest.json` и скриптами;
- `/audit/candidate-v6/src`: отдельная копия исходников с патчем;
- `/input`: read-only снимки PDF, имя каждого — `<sha256>.pdf`;
- `/out`: единственный writable каталог с временными результатами;
- `PYTHONPATH`: исследуемые исходники, временные библиотеки PDFium и `/audit`;
- `PDF_CLEANUP_SOURCE_COMMIT=uncommitted`, `TMPDIR=/out`.

Manifest содержит `documents` (все относительные пути/хеши/размеры),
`unique_documents` (один представитель каждого SHA256), `cloud_baseline`
(контрольные хеши оригиналов, существующих cleaned и INDEX). Нельзя использовать
production originals как writable `/out`. PDF и изображения в Git не сохранены.
Применялись Docker `--read-only`, `--network none`, user `1000:1000`, read-only
bind mounts `/audit` и `/input`. Запуск через Python entrypoint.

`corpus_runner.py` создаёт результаты и сохраняет план удаления; `test_research.py`
проверяет исправления и содержит один **expected failure** для известной ошибки
семантического распознавания. `test_reviewer.py` проверяет независимый verifier
на сохранности, повреждениях, пересечении масок, crop и поворотах.
`review_pdfium.py` сравнивает все страницы, свойства документа и основной текст.

`final_review_runner.py` — восстановление конкретной завершённой серии:
он перепроверяет текст 46 старых результатов, сохраняя уже проверенные растры,
и проверяет три результата `/out/repaired-v6`. Он не является универсальным
production runner. Историческая генерация 46 результатов была выполнена V1,
затем усиленно проверена V4; три отказа исправлены V6. Нельзя выдавать такую
смешанную серию за полный прогон одного окончательного алгоритма.

`operator_first.py` и `hybrid_page_probe.py` — диагностические эксперименты
на WR6220 G5. Имя/страница заданы только для воспроизведения конкретного дефекта;
они не входят в CLI и не предлагаются как правила production.

## Известные ограничения

- В V6 сохранилась ошибка классификации нумерованного основного текста.
- Повторная обработка некоторых уже очищенных PDF выбирает полезные строки
  либо отказывает; идемпотентность не подтверждена.
- Строгая проверка PDFium выявила изменения вне масок у части результатов
  региональной redaction. Они не объявлены безвредными.
- Полная замена redaction текстовыми операторами не прошла усиленную проверку
  одного документа; выбор метода ещё требует исследования.
- В неизменённом upstream suite один тест ожидает отказ при пересечении
  bounding boxes. V6 сохраняет основной текст точечным удалением и потому
  нарушает прежнее ожидание отказа; отдельный положительный контроль проверен.

Тестовые логи сохраняют как успешные, так и отрицательные результаты и дефекты
самого исследовательского verifier. Это не production acceptance.
